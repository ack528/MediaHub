# 更新日志

> 每次发布时同步到 GitHub Release 的说明里;手机端「设置 → 关于 → 更新说明」和管理程序「关于 → 更新说明」会显示这里的内容(随程序打包)。
> 版本号分开计:手机端(LocalBrowse)和服务端 / 管理程序(MediaHub)各自一套。

## 手机端 LocalBrowse

### 2.14.0 · 2026-10-08
- **检查更新更快更稳**:内置 4 个 GitHub 下载镜像(ghfast.top、gh-proxy.com、ghproxy.net、gh.llkk.cc)。直连 github.com 和各个镜像同时探测,谁先响应用谁,直连慢或不通时自动换镜像。
- **备用 DNS**:更新用的域名先走 DoH(阿里 DNS、DNSPod、Cloudflare、Google,依次尝试),系统 DNS 返回被污染的地址时也能连上;结果缓存 10 分钟。
- 校验和(SHA256SUMS.txt)仍然优先直连获取;镜像只负责搬安装包,安装包的 SHA-256 必须和校验和一致才会安装。
- 需要服务端 1.9.0 才有同样的镜像和备用 DNS 支持(服务端会自动更新)。

### 2.13.0 · 2026-10-08
- 新增**强制屏幕保持 120 Hz 及以上**(设置 → 外观 → 屏幕,默认开启):应用在前台时,让系统把屏幕固定在同分辨率下刷新率 ≥ 120 Hz 的最高档(例如 120 / 144 Hz);屏幕没有这样的档位(60 / 90 Hz)就不起作用。回到前台、显示模式变化时自动重新套用;补帧申请的刷新率也不低于这个档位。系统省电模式 / 过热降频 / 在系统设置里手动锁定刷新率时,系统仍可能覆盖。

### 2.12.1 · 2026-10-08
- **本地媒体浏览提速**。有的手机上读取本机媒体每次要 10 秒。原来每次进入文件夹列表都强制重新读两遍媒体库,并发的请求还各自排队再读一遍。现在只在媒体库真的变化时才重读(新拍 / 删除会自动感知),图片和视频并行读取,启动时就在后台预读,并发请求共用同一次读取。
- 缩略图限流(同时最多 3 张,避免几千万像素的照片同时解码把 256MB 堆撑满),小尺寸优先用系统缓存的缩略图。
- 日志里新增耗时记录:读取媒体库的图片 / 视频各用了多少毫秒、超过 0.5 秒的接口和超过 0.4 秒的缩略图(含文件大小和尺寸),方便定位哪里慢。

### 2.12.0 · 2026-10-08
- **天玑 / Mali 上补帧不再重影、扭曲**。根因是 Mali 驱动对"带纹素偏移的采样"算错,补帧的光流从第二阶段起全部偏离,运动画面只剩前后帧混合(静止画面正常,所以之前没查出来)。现在加载着色器时把偏移换算进采样坐标绕开,只对 Mali GPU 生效。用有真值的测试片段验证:修复后天玑 9500 的补帧误差和 Intel GPU 一致,约为简单混合的一半。
- 修复光流精度参数传反,光流终于按设置的精度计算。天玑 9500 上一次 ×5 生成从约 36ms 降到约 15ms。
- 补帧不再只限高通处理器,天玑 / Mali 等 Vulkan 设备都可以用。
- 系统短暂把屏幕降到 60Hz 时,补帧会话保留 5 秒以上才释放,不再每次重建(以前每次卡 0.5 ~ 0.7 秒)。
- 补帧倍率按"60Hz 和 120Hz 下都规则"选(24fps 低功耗改为 ×5,原来 ×2 = 48fps 在 60Hz 上每 5 帧停顿一次),上屏节奏更均匀。
- 补帧倍率改用视频声明的帧率决定,4K / 高码率视频解码吃力时不再倍率乱跳、反复重建会话。
- 补帧的输入分辨率上限约 1080p(高帧率视频约 720p),4K 视频在 1080p 级别上生成、上屏时放大,真实帧仍是原分辨率。
- 自动降级的光流精度只在 100% / 75% / 50% 之间调整,再不够就减半生成倍数、降输入分辨率。

### 2.10.0 · 2026-10-07

### 2.9.0 · 2026-10-07

## 服务端 / 管理程序 MediaHub

### 1.9.0 · 2026-10-08
- **检查更新更快更稳**:内置 4 个 GitHub 下载镜像,直连和镜像同时探测,谁先响应用谁;直连慢或不通时自动换镜像。配置 `update.mirrors` 可改列表(`[]` = 不用镜像),`update.mirror` 是自己指定的、排最前面的镜像。
- **备用 DNS**:更新用的域名先走 DoH(阿里 DNS、DNSPod、Cloudflare、Google 依次尝试),系统 DNS 失败或返回被污染的地址时也能连上;结果缓存 10 分钟。
- 校验和仍然优先直连获取;镜像搬运的更新包必须通过 SHA-256 校验才会安装。

### 1.8.0 · 2026-10-07
- 新增 `POST /api/v1/random/reset`:清除所有历史随机序列,换一个新的「盐」(存进数据库,重启后不变)并在后台重新生成全部序列(手机端侧边栏「重新生成随机序列」使用)。

### 1.7.0 · 2026-10-07
- **随机序列提前准备**:启动时在后台为「全部」和每个盘符 × 3 种类型(全部 / 图片 / 视频)预先生成 12 份固定的随机序列(每份 600 个),请求时直接切片取,不再临场随机查找;只有该范围扫进了新文件才会重新生成。
- `GET /api/v1/random` 新增 `seed` + `batch` 参数:seed 选用哪一份序列(1..12),同一个 seed 的第 batch 批永远是同一批,换 seed 才换序列;不带 seed 仍是每次都不同。

### 1.6.0 · 2026-10-07
- 随机浏览**启动即预热**:服务端启动时就在后台算好各盘符的媒体 id 范围、并各取几批随机条目把数据库页读进缓存,之后每 10 分钟刷新一次;第一次点随机浏览不再等冷读盘。
- 修复随机浏览接口在大库上很慢甚至超时(整表扫描要几十秒):请求只查预热好的范围表,取点时沿主键往后找,单次请求最多花 4 秒,到点有多少返回多少。
- `GET /api/v1/random` 新增 `roots` 参数(根目录 id,逗号分隔),只在这些根目录(一个盘符)里随机。

### 1.5.0 · 2026-10-07
