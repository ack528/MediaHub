# 更新日志

> 每次发布时同步到 GitHub Release 的说明里;手机端「设置 → 关于 → 更新说明」和管理程序「关于 → 更新说明」会显示这里的内容(随程序打包)。
> 版本号分开计:手机端(LocalBrowse)和服务端 / 管理程序(MediaHub)各自一套,哪一端有改动才发哪一端。
> 写法约定:每个版本几条短句,纯文本(不用加粗、代码标记和嵌套列表),方便在手机和管理程序里直接显示。

## 服务端 / 管理程序 MediaHub

### 3.3.0 · 2026-10-18
- 新增:检查更新时顺便把最新的手机端安装包下载到数据目录,手机检查更新直接从服务器下载,不用每台手机自己连 GitHub。管理程序「关于」里能看到缓存状态;config.json 的 update.cacheApp 可关。
- 优化:检查更新时 GitHub API、直连和各镜像同时请求,谁先拿到用谁(以前一个接一个试,网络差时要几分钟);DoH 域名解析并发;下载 30 秒没有数据就换下一个地址。

### 3.2.5 · 2026-10-18
- 优化:转码播放拖动进度条后等待更短。转码改用核显硬件解码(失败自动退回软解),重启 ffmpeg 的探测量调小,并按实际产出速度决定是等 ffmpeg 追上还是直接从目标位置重新转。

### 3.2.4 · 2026-10-18
- 修复:什么都没做 CPU 却很高。原因是图片占位图的后台补算:几十万张图片逐张起 ffmpeg 进程,9 个盘同时跑。已取消后台整库补算,改为生成缩略图时顺手算。

### 3.2.3 · 2026-10-18
- 修复:启动后部分盘符显示 0 个文件(实际有媒体),现在直接显示索引库里的数量。
- 修复更新说明显示:星号等标记符号、版本标题错乱;历史版本日志全部改为简短条目。

### 3.2.2 · 2026-10-18
- 修复:存储优化的暂停 / 继续无效。暂停现在会挂起正在压缩的 ffmpeg,状态重启后保持。
- 压缩时 CPU 占用大幅降低:核显硬件解码加硬件编码优先,软件线程数受限,空闲优先级。
- 新增只在指定时段压缩(如 01:00-07:00)。
- 压缩队列每个视频加定位按钮,在资源管理器里选中视频。

### 3.2.1 · 2026-10-18
- 修复管理程序界面白屏;加错误边界,单个页面出错不再影响整个窗口。
- 压缩队列新增失败原因汇总、重试全部失败项、只看失败的;旧校验误判的失败自动重新排队。

### 3.2.0 · 2026-10-18
- 登录失败全局锁定:任何设备失败后,所有设备 20 秒内不能再验证密码。
- 修复压缩常失败:校验不再被无害警告误判,编码失败依次退到更稳的方式。
- 压缩校验通过后自动替换原文件,原文件进回收区,7 天后自动清理。
- 转码更稳:单个文件硬编失败不再关掉整个服务的 QSV,容错残缺文件和奇数宽高。
- 兼容版本:只转音频、视频原样复制,缓存在媒体盘。
- 实时增量索引:新增 / 删除 / 改名的文件几秒后自动进索引。
- 缩略图更快,图片占位图后台补算;数据库调优并每日自动备份,搜索用游标翻页,列表接口支持 304。
- 同一数据目录只允许一个服务进程;日志降噪;可录制 CPU 剖析。
