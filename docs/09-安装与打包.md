# 09 安装与打包

版本 1.1.1。打包产物都在项目的 `dist\` 目录,由 `tools\package.ps1` 一键生成。

| 文件 | 说明 |
|---|---|
| `MediaHub-1.1.1-setup.exe` | 服务端 + 桌面管理程序的安装包(NSIS,中文界面,装到当前用户目录,不需要管理员权限) |
| `MediaHub-1.1.1-portable.zip` | 便携版:解压即用,放在 NAS 任意目录 |
| `LocalBrowse-1.1.1.apk` | Android 手机客户端(已签名的发布版,Android 8.0+) |
| `SHA256SUMS.txt` | 校验和 |

## 一、NAS(Windows)上安装服务端

1. 运行 `MediaHub-1.1.1-setup.exe`(或解压便携版,双击 `MediaHub.exe`)。
2. 打开 MediaHub:
   - **媒体库** 页直接选盘符(比如 `D:\`、`E:\`),可给每个盘起一个短名字(手机上显示为分组标签);盘符下每个母文件夹是一个群,规则见第六节。
   - **账号** 页创建登录手机用的账号和密码。
   - **概览** 页点「启动服务」。第一次启动会先扫描并读取元数据,大库需要几分钟到几十分钟。
3. **防火墙**:第一次启动时 Windows 可能弹出防火墙询问,选择允许「专用网络」。若没弹窗,手动放行 TCP 端口 8480(默认,可在「网络」页修改)。
4. 记下「网络」页里列出的本机局域网地址,例如 `192.168.1.20:8480`。

服务由管理程序启动后独立运行,关掉管理界面不影响手机访问。

安装包里已包含 `ffmpeg / ffprobe / ExifTool`(读取拍摄时间、尺寸、生成视频封面),不用另外安装。

### 可选:Jellyfin(视频转码与现成封面)

不装 Jellyfin 也能浏览、播放手机能直接解码的视频。需要转码(比如 mpg/wmv/杜比视界)或想复用 Jellyfin 已生成的封面时:

1. 自己安装 Jellyfin(便携版或安装版均可),让它只监听本机 `127.0.0.1:8096`,并把同样的媒体文件夹加为它的媒体库。
2. 在 Jellyfin 管理后台创建一个 API 密钥。
3. 在 MediaHub「视频转码 → Jellyfin」页填入地址和密钥。
4. Intel 核显转码(QSV)要在 NAS 的 BIOS 里保持核显启用。转码功能本身是下一阶段(M3)的内容。

### 数据放在哪里

- 数据库、日志:默认 `C:\MediaHub\data`(建议放固态盘,可在「存储」页修改)。
- 配置:安装目录下 `runtime\mediahub\config.json`。升级安装不会覆盖它。
- 视频封面缓存:放在每个媒体盘根目录的隐藏文件夹 `.mediahub`(每盘上限默认 50 GB,空间不够时自动改放安装目录的 `runtime\cache`)。**服务端除了这个缓存目录,不会往媒体盘写任何东西。**

## 二、手机安装

1. 把 `LocalBrowse-1.1.1.apk` 传到手机(数据线、局域网共享、聊天软件均可),点开安装,允许「安装未知来源应用」。
2. 首次打开会请求「附近设备 / 本地网络」权限,**必须允许**,否则 Android 17 连不上局域网地址。
3. 输入服务器地址(如 `192.168.1.20:8480`),点「连接」,再输入账号密码登录。

升级时直接覆盖安装即可(签名一致,数据保留)。

## 三、手机端设置一览(列表页左上角菜单 → 设置)

- **外观**:跟随系统 / 浅色 / 深色;聊天背景(渐变 / 纯色);日期胶囊开关。
- **浏览**:记住每个文件夹的浏览位置;聊天流最新在底部;网格默认列数;快速滑动时暂停加载缩略图。
- **图片**:磁盘缓存上限(128 MB–4 GB)、内存缓存比例、硬件位图、淡入动画(重启生效)。
- **视频播放**:自动播放、循环、静音、默认倍速、记住播放进度、快进快退步长、画面缩放、控制条隐藏时间、屏幕常亮、播放技术信息(解码器 / 码率 / 丢帧)。
- **编解码器**:解码方式(自动 / 硬件优先 / 软件优先 / 仅硬件 / 仅软件)、解码失败自动改软解、备用解码器、MediaCodec 异步队列、隧道播放、缓冲大小、最大分辨率 / 码率(给转码用)、首选音轨语言、内嵌字幕;并可查看**本机解码器列表**(每种格式的解码器、硬件 / 软件、最大分辨率)。
- **网络**:连接超时、读取超时。
- **存储与缓存**:清除图片缓存、清除浏览位置、清除播放进度、恢复默认设置。
- **服务器与账号**:当前服务器、退出登录。

## 四、自己重新打包

```powershell
powershell -File tools\package.ps1                # 全部(服务端测试 → 安装包 → 便携版 → APK)
powershell -File tools\package.ps1 -SkipAndroid   # 只打桌面端
powershell -File tools\package.ps1 -SkipDesktop   # 只打安卓端
```

- 前提:已运行过 `tools\setup.ps1`(便携工具链)。桌面端打包需要 Rust(MSVC)与 Node,NSIS 工具已缓存在 `%LOCALAPPDATA%\tauri\NSIS`。
- Android 发布签名:密钥库与口令在 `signing\`(`localtg-release.jks`、`keystore.properties`),**请自己备份且不要外传**;丢失后新 APK 无法覆盖安装旧版。没有 `signing\` 时 release 改用调试签名。
- 版本号要同步改:`android\app\build.gradle.kts`(`versionName` / `versionCode`)、`server\cmd\mediahub\main.go` 的 `version`、`desktop\package.json`(及 `package-lock.json`)、`desktop\src-tauri\Cargo.toml` / `tauri.conf.json` / `tauri.bundle.conf.json`、`tools\package.ps1` 的 `$Version`(该文件需保持 UTF-8 BOM)。

## 五、已知限制(1.1.1)

- 安装包没有数字签名,Windows SmartScreen 可能提示「未知发布者」,点「更多信息 → 仍要运行」。
- 安装包不含 libvips:HEIC / RAW 等由 ffmpeg / ExifTool 转换,**JXL 需要 libvips**(可选,放到 `tools\vips\bin\vips.exe` 即可,不放则 JXL 在手机上无法显示)。
- 视频转码:服务端内置 ffmpeg 转码(不依赖 Jellyfin),配置了 Jellyfin 且已收录该视频时优先用 Jellyfin。手机能直接解码的视频不经过转码。
- 手机端颜色和圆角是按 Telegram 近似调的,需要在真机上再微调。
- 模拟器的软解码器能力有限(例如 1080p60、HEVC Main10),真机以硬解为准。
- 手机让 Windows 防火墙放行端口:管理程序「网络 → 开机与防火墙」有一键放行(会弹 UAC 确认)。

## 六、文件夹如何变成群组(0.3.0 起)

- 在 MediaHub「媒体库」页**直接选盘符**(例如 `D:\`、`E:\`)。盘符本身是手机上的一个分组标签(顶部的 `D:` / `E:`)。
- 盘符下的每个**母文件夹**是一个群,群名就是文件夹名。
- 母文件夹里无论嵌套多少层子文件夹,都**不再单独成群**:里面所有的图片和视频平铺进这个母文件夹的群里(按时间排序)。
- 直接放在盘符根目录的媒体,归入以盘符命名的群(没有就没有这个群)。
- 空文件夹、只含非媒体文件的文件夹不显示。
- 母文件夹或子文件夹改名、文件在子文件夹之间移动,群和媒体的 ID 都不变,手机上记住的浏览位置不丢;文件从一个母文件夹移到另一个母文件夹,会换群。
- 升级到 0.3.0 及以后版本后第一次启动会自动重新扫描并按新规则分组,不需要手动清理。

## 八、界面动画

设置 → 外观 → 界面动画:

- **滑动 + 视差**(默认):新页面从右侧整屏滑入,旧页面后退 1/4 屏,返回时反向;支持 Android 的预测性返回手势。
- **Material 共享轴**:位移约 1/10 屏宽 + 淡入淡出(Material Motion 规范)。
- **仅淡入淡出**、**关闭动画**。
- 点开图片 / 视频时,缩略图直接放大成全屏(共享元素,容器转换),返回时缩回原位;聊天流与网格切换使用淡入加轻微缩放;登录与列表之间使用 fade through。

## 九、日志与问题反馈

手机端 设置 → 日志与诊断:

- 日志级别:关闭 / 仅错误与警告 / 信息(默认)/ 调试(含每个网络请求和播放器事件)。
- 应用崩溃时会自动保存崩溃报告(堆栈、设备信息、最近日志、系统 logcat),**下次启动弹出"上次异常退出了"**,可一键分享或复制。
- 「分享日志文件」打包成 zip(设备信息、应用日志、崩溃报告、logcat)用系统分享发出;「复制最近日志到剪贴板」可直接粘贴到聊天里。
- 「查看日志」可在应用内直接看,支持只看警告和错误。
- 遇到问题:先把日志级别调到"调试",重现一次,再分享日志。

服务端日志在 `C:\MediaHub\data\logs\`(管理程序「日志」页可查看)。

## 十、扫描:续扫、跳过、实时速度(0.4.0)

- **实时速度**:管理程序「概览 → 索引进度」每个盘显示实时速度——扫描阶段是"xxx 文件/秒",读取元数据阶段是"已读 N / 总数 · xx 个/秒 · 预计还需 x 分钟"。速度由服务端每秒采样并平滑。
- **扫到一半关闭,下次接着扫**:每个母文件夹扫完就会记一笔,服务再次启动时只扫没扫完的母文件夹,并提示"接着上次中断的扫描继续";元数据读取和封面预热本来就只处理没做完的部分。
- **完整扫描过的盘,启动时不再重扫**:距上次完整扫描不足"启动时复用上次扫描的时限"(默认 12 小时,「媒体库 → 扫描与过滤」可改,0 = 每次启动都扫)就直接跳过。新添加的盘、被中断的盘、超过时限的盘仍会扫描。
- **定时重新扫描**:服务运行期间每隔"定时重新扫描间隔"(默认 24 小时,0 = 不定时)自动扫一遍,发现新增、删除和改名。
- **手动「重新扫描」**:丢弃中断记录,从头完整扫一遍。
- **从旧版本升级**:数据库启动时立即把旧版"每个文件夹一个群"的数据整理成"母文件夹一个群"(子文件夹的群被删除,媒体并入母文件夹),不用等扫描;接口也只返回母文件夹。

- **回到最新**:聊天流往上翻一段后,右下角出现圆形按钮,一键回到最新(网格里是回到顶部)。

- 群头像是圆角方块;logo(蓝色相框 + 服务器底座)与桌面端一致,用作应用图标、侧边栏头部和登录页。

## 十二、1.0.0 新增

### 视频与图片
- **服务端转码**:手机解码不了的视频,播放器报错后自动改走 Jellyfin 的 HLS 转码(QSV 硬件加速),也可在播放器「更多 → 画质 / 转码」手动选 1080p / 720p / 480p。服务启动时自动在 Jellyfin 里为每个盘创建媒体库(名称 `MediaHub <盘符>`)并同步硬件加速设置;退出播放会通知服务端停止转码。
- **服务端图片转换**(`render`):HEIC / HEIF / AVIF、RAW(内嵌预览)、TIFF 等手机无法显示的格式由服务端转成 JPEG。设置里「HEIC 显示方式」可选手机本地解码或服务端转换。

### 损坏 / 不完整文件的识别
- 之前"很多视频打不开、没有预览图、播放一半报错"的原因是 **NAS 上的文件本身不完整**(下载中断留下的 0 字节或被截断的文件),不是网络问题。
- 服务端扫描时检查 MP4 / MOV 的结构(顶层 box 超出文件末尾、缺少 moov 即判为不完整),0 字节文件直接标记。接口给每个条目带 `flags.corrupt / flags.truncated` 和中文原因 `problem`。
- 手机端:损坏的文件显示警告图标和"文件损坏 / 空文件"占位,不再是一块空白;不完整的视频带"不完整"标签,点开后提示"播放到被截断处会停止";错误提示翻译成人话(下载中断、文件已不存在、登录失效、网络问题等);完全损坏的视频不创建播放器,可选"仍然尝试播放"。
- 快速滑动时被暂停的请求(本地返回 504)不再记成错误。

### 服务端日志与目录读取失败
- **日志系统**(`internal/logx`):写到 `<数据目录>\logs\mediahub-日期.log`,单个文件超过 20 MB 自动切分,保留最近 14 天且总量不超过 300 MB;内存里留最近 3000 行;`stderr.log` 记录运行时致命错误。
- **崩溃捕获**:所有后台协程和 HTTP 请求里的 panic 都被捕获,记日志并写 `crash-时间.txt`(堆栈、运行环境、最近 300 行日志),服务继续运行;主流程崩溃也会先写报告。
- **日志级别**:管理程序「日志 → 日志设置」可选 调试 / 信息 / 警告 / 错误(默认信息),修改后重启服务生效。
- **管理程序「日志」页**:按级别过滤、关键字搜索、颜色区分、停在底部时自动跟随;「导出日志包」把全部日志和崩溃报告打成 zip(不含密码、令牌和 API 密钥),服务没运行也能导出;列出崩溃报告,一键打开。
- 日志接口(`/api/v1/admin/logs`、`/logs/bundle`、`/logs/level`)只接受本机回环地址 + 管理密钥,普通用户令牌不能访问。
- **目录读取失败分类**:概览页每个盘的"跳过 / 失败的目录"可展开,按原因分为 没有权限(系统保护目录,正常)、已不存在(被删除,正常)、盘不可用(移动硬盘断开、网络盘掉线)、读取出错(硬盘坏道)等,附 Windows 错误码。系统保护目录(`System Volume Information`、`$RECYCLE.BIN`、`Recovery` 等)总是跳过,不再产生"读取失败"。

### 桌面管理程序
- 托盘菜单增加「启动服务 / 停止服务 / 重新扫描媒体库」。
- 「网络 → 开机与防火墙」:开机自启(写当前用户的 Run 注册表项,启动后只留托盘)、"打开管理程序时自动启动服务"、防火墙状态检测与一键放行(UAC)。

### 手机端
- 令牌改为 Android Keystore 的 AES-GCM 加密存储;旧版本留下的明文令牌升级后自动转为密文。
- 聊天页「更多 → 跳转到日期…」(按时间排序时):选一个日期,列表重建并停在该日附近。
- 查看器「保存到手机」(图片顶栏按钮、视频更多菜单):原文件保存到 图片/MediaHub 或 影片/MediaHub,相册里可见(Android 10+ 不需要存储权限)。

## 十三、1.1.0 新增

### 加密传输(HTTPS)
- 手机与服务器之间默认走 **HTTPS**:服务端第一次启动时生成一张 ECDSA P-256 自签名证书(10 年,存在数据目录 `tls-cert.pem` / `tls-key.pem`),TLS 1.3 + HTTP/2(Go 会按手机有没有 AES 硬件加速自动选 AES-GCM 或 ChaCha20-Poly1305),握手快、吞吐高。
- **证书固定**:手机第一次连接时先读取服务器证书的 SHA-256 指纹并显示出来,请和管理程序「网络 → 证书指纹」显示的核对,一致再点「信任并连接」。以后手机只接受这张证书(不依赖 IP,换 IP 也能连);证书变了(服务器重装 / 被冒充)会拒绝连接并提示重新核对。
- 管理程序走**仅本机的明文端口**(监听端口 + 1,例如 8481,只监听 127.0.0.1;可用 `adminListen` 改),不必处理自签名证书。对外的 8480 是 HTTPS,明文访问会返回 400。
- 可在「网络 → 监听与访问」关闭加密传输(退回明文 HTTP,不推荐)。
- 从旧版本升级:手机上旧的 `http://` 登录会被识别为失效,弹出登录页并提示重新连接、核对指纹。
- 登录令牌继续由 Android Keystore 加密保存。

### 转码不再依赖 Jellyfin
- 原因:真机上点「转码」一直报 503 —— 你的 NAS 没配置 Jellyfin,服务端返回"未启用转码"。
- 现在服务端自带 **ffmpeg HLS 转码**(`internal/api/hls.go`):先按视频总时长生成完整的 VOD 播放列表(4 秒一段),段在手机请求到时才由 ffmpeg 现转;拖动进度条 / 从上次位置继续 / 回看都会从对应的段重新启动 ffmpeg(精确定位),时间轴和原视频一致。
- 英特尔核显 QSV 硬件编码(`h264_qsv`,必须加 `-forced_idr 1`,否则关键帧不按 4 秒对齐),失败自动退回 libx264 软编;同时转码路数受「同时转码路数」限制;转码进度领先播放太多会自动暂停,退出播放 / 空闲 90 秒清理临时文件。
- 配置:「视频转码 → 转码引擎」选"自动"(有 Jellyfin 且已收录该视频就用它,否则内置)或"只用内置 ffmpeg"。

### 重新添加文件夹不再重扫
- 配置里移除的盘 / 文件夹只是"停用"(手机上不再显示),索引数据保留;再次添加(路径不区分大小写)时直接复用,启动时不重新扫描(需要时点「重新扫描」)。盘换了(卷序列号变化)则旧数据作废,重新扫描。
- 从 0.4.0 之前的版本升级:数据库迁移 v6 把"已有索引数据"的盘标记为已完整扫描过,升级后不会整盘重扫。

### 目录读取错误 123
- "文件名、目录名或卷标语法不正确(错误码 123)"多半是文件夹名以空格 / 点结尾,或是 Windows 保留名(CON、NUL、COM1……)、含 `? * :` 等字符(Linux / Mac 创建的)。Win32 普通路径会把这些名称"规范化"掉,于是找不到目录。
- 现在遇到这类错误会自动改用**扩展路径(`\\?\` 前缀)**重试,读目录、读文件、取元数据、转换图片、转码都支持;仍然失败的目录归为"名称不合法"(跳过,概览页可展开看到路径和原因,改个名字即可)。
- 顺手修了一个旧 bug:超长路径(≥240 字符)的扩展路径前缀写成了 `\?\`(少一个反斜杠)。

### 返回动画
- 研究了几个开源实现:Telegram(`ActionBarLayout`:上层页面 1:1 跟手、下层页面静止 + 变暗、左边缘投影、松手按位置 / 速度判定、ease-out-quint 收尾)、Voyager 的预测性返回(`SeekableTransitionState` + 手势进度映射)、Navigation Compose 2.10 的 `predictivePopEnterTransition / predictivePopExitTransition`(参数是手势起始边)、Navigation 3 的 `predictivePopTransitionSpec`。
- 发现的问题:① 手势返回没有自己的规格,导航库的默认预测性动画是"页面缩成一张卡片 + 淡出",和按钮返回的滑动完全不一致,松手后还会停一下再消失;② 手势进度是按"播放进度"去 seek 动画的,所以规格必须是线性缓动才能 1:1 跟手(原来用的减速曲线让页面在手指刚动时就跳出一截);③ 视频页的 SurfaceView 不会跟着页面一起缩放 / 淡出(它在窗口后面"挖洞"显示),退出时视频画面原地不动,只有控制条缩小。
- 现在:层级页面(列表 ← 聊天 ← 设置)手势返回 = 线性 + 整屏跟手滑出,下层页面从 1/4 屏视差滑回,上层页面左边缘有投影;支持从右边缘划;查看器手势返回 = 整页缩小淡出;页面开始退出时对 SurfaceView 用 `PixelCopy` 截图盖在上面再把 SurfaceView 藏起来,视频画面也跟着缩放淡出;手势取消时恢复。
- 注意:测试时曾把"界面动画"设成了"仅淡入淡出",此时返回只有淡入淡出(没有滑动)是预期行为;默认是"滑动 + 视差"。

### 画质增强(实验):实时超分 / 补帧 / SDR 转 HDR
- 设置 → 画质增强(实验),播放时「更多 → 画质增强」也能快速切换。开启任意一项后,视频改由本应用自己的 OpenGL ES 3 渲染器显示(`render/` 包);全关时仍走普通播放,不受影响。
- 结构:ExoPlayer 解码到 SurfaceTexture → 每个源帧:OES→RGBA16F →(超分)→ 帧环形缓冲(+亮度金字塔 +运动估计)→ 每个屏幕刷新(vsync):按 ExoPlayer 给出的上屏时间取相邻两帧 →(插帧)→(SDR→HDR)→ 窗口表面。SurfaceTexture 的时间戳就是 `releaseOutputBuffer` 的上屏时间,帧比上屏时间早到,所以能在两个真实帧之间插值。
- **超分**:直接运行开源的 mpv 用户着色器(自己实现了 `//!HOOK/BIND/SAVE/WIDTH/HEIGHT/WHEN` 的最小运行时,`render/MpvShader.kt`):FSR 1.0(AMD,agyild 的 mpv 移植,MIT,通用、很快)、Anime4K v4(bloc97,MIT,CNN,动漫线条更干净;小 / 中两档)。着色器在 `assets/shaders/`。视频高度超过设定值(默认 900p)不处理;处理耗时连续 2 秒超过帧间隔 90% 时自动停用超分。
- **补帧**:帧混合(便宜,有轻微拖影);运动补偿(实验):亮度三层金字塔块匹配(1/8 层 ±8 全搜索,1/4、1/2 层精修,再做半像素 / 四分之一像素精修),上屏时每个像素在自己与相邻 4 个块的运动向量里挑"前后帧对得最齐"的,匹配不可信的退回混合,差异再大保持最近的帧。补帧时画面整体晚一个源帧间隔(≤50ms)上屏,换取"下一帧"已经到达。屏幕刷新率不够高(< 源帧率的 1.3 倍)时自动不补。模拟器上测得:匀速运动方块的位置残差 RMS 0.21 源像素(帧混合 0.74)。
- **SDR→HDR**:高光扩展的逆色调映射(只抬高光,阴影和中间调不变;大面积亮区少抬,避免整屏刺眼;参考白 203 nit,峰值可选 400–1000 nit)→ BT.709→BT.2020 → PQ,输出到 `EGL_EXT_gl_colorspace_bt2020_pq` 的 10 位窗口表面(窗口切到 HDR 色彩模式),由系统按屏幕能力做色调映射。模拟器没有 HDR 屏,**这一项只通过了编译和着色器链接,没有实机验证**;表面创建失败会自动退回 SDR 并在统计信息里提示。HDR 片源本身不处理。
- 播放页的「显示技术信息」会显示增强渲染的状态:输出帧率、处理耗时、是否因性能停用、HDR 是否生效。
- 开源来源:Anime4K <https://github.com/bloc97/Anime4K>(MIT);FSR 1.0 mpv 移植 <https://gist.github.com/agyild/82219c545228d70c5604f865ce0b0ce5>(MIT);SDR→HDR 的思路参考 <https://github.com/96dot/SDR-to-HDR-Video>(MIT,WebGPU 版);评估过但未采用:RIFE(rife-ncnn-vulkan,神经网络补帧,需要 NDK + Vulkan,手机上实时 1080p 不现实)、Media3 `setVideoEffects`(帧进帧出、不能输出 HDR)。

## 十四、1.1.1:界面转场改成系统风格

- 研究了 Clash Meta for Android(`MetaCubeX/ClashMetaForAndroid`)和 Shizuku(`RikkaApps/Shizuku`):它们都是**多 Activity 应用**,界面之间的前进 / 返回动画**没有自己写**,用的是系统的 Activity 转场(Shizuku 在 manifest 里加了 `android:enableOnBackInvokedCallback="true"` 以启用系统的预测性返回,Clash Meta 直接用默认主题),所以看起来和系统应用一样顺。
- 系统的转场参数(AOSP `activity_open_enter / activity_open_exit / activity_close_enter / activity_close_exit` 与 `fast_out_extra_slow_in`):**只平移 96dp(不是整屏)**,450ms;进入的页面 83ms 淡入(延迟 50ms),离开的页面 83ms 淡出(延迟 35ms);缓动是两段贝塞尔拼成的 Emphasized 曲线 `M0,0 C0.05,0 0.133333,0.06 0.166666,0.4 C0.208333,0.82 0.25,1 1,1` —— 前 1/6 时间先加速,再长长地减速。
- 以前的默认(整屏滑动 + `EmphasizedDecelerate`)生硬的原因:减速曲线一上来就是最大速度,约 70ms 内就走完 90% 的位移,剩下 380ms 几乎看不出变化,视觉上像"闪一下就换了页";而且整屏位移太大。录屏逐帧测过:按钮返回的可见变化只有 4~6 帧(65~100ms),单帧最大跳变占总位移的 70%。
- 现在「界面动画」默认 = **系统风格**:用 AOSP 的参数在 Compose 里复现;手势返回仿系统的跨 Activity 预测性返回(离开的页面缩到 90%、带 28dp 圆角、朝手指一侧偏移、最后淡出,下面的页面带一层随进度变亮的遮罩),全部线性缓动保证跟手。原来的整屏滑动改名「整屏滑动 + 视差(Telegram 式)」,仍可选(带左边缘投影)。
- 排除了一个误判:前进转场里偶尔看到的"一秒卡顿"是测试脚本用 uiautomator 取控件时屏幕静止造成的;不经过 uiautomator 的录屏显示前进转场是连续的 ~28 帧。
- 测试脚本:`testdata/scripts/nav-anim-test.ps1`(所有页面的前进 / 按钮返回 / 手势返回录屏)、`anim-sheet.py`(把转场逐帧拼图)、`anim-curve.py`。

## 十五、1.1.2(仅手机端):每个页面一个 Activity,转场完全交给系统

- 只在 1.1.1 的基础上改了手机端(服务端 / 管理程序仍是 1.1.1)。**这一版按用户要求没有做实机 / 模拟器测试,只保证编译通过**。
- 已经把参考项目克隆到本地:`参考项目\ClashMetaForAndroid`、`参考项目\Shizuku`(浅克隆,已加入 .gitignore)。读源码的结论:两个项目都**没有自己写任何页面转场**,界面都是 Activity,`startActivity()` 进、`finish()` / 系统返回手势出(Shizuku 额外在 manifest 里开了 `android:enableOnBackInvokedCallback="true"` 启用系统的预测性返回),动画全部由系统负责。
- 照着重写:原来的"一个 Activity + Compose NavHost 自己画转场"拆成
  - `MainActivity`:登录页 + 文件夹列表;
  - `ChatActivity`:一个文件夹的聊天 / 网格(里面的"缩略图 ↔ 全屏查看器"仍用共享元素,系统转场做不到);
  - `SettingsActivity`:设置根列表和**每个分类页各自一个实例**(和 Clash Meta 的每个设置页一个 Activity 一样);
  - `SearchActivity`:搜索(查看器同上)。
  进入用 `startActivity`,返回用 `finish()` / 系统返回手势,动画是系统的 Activity 转场 + 系统的跨 Activity 预测性返回(缩小 + 圆角 + 跟手),由系统进程里的窗口动画驱动,不受应用主线程卡顿影响 —— 这是"生硬"的根本解法。
- 为了系统转场不闪:主题的 `windowBackground` 按浅色 / 深色分别设成页面底色(`values/colors.xml`、`values-night/colors.xml`),并在每个 Activity 里按应用的"颜色主题"设置同步窗口背景。
- 细节:二级页面登录失效(401 / 退出登录)时自己 `finish()`,露出下面的登录页;小窗(画中画)回调抽到基类 `TgActivity`,聊天 / 搜索页都支持;Activity 内的 NavHost 只剩"根页面 + 查看器"。
- 可能的副作用:每个 Activity 首次组合比单 Activity 内切换稍慢(窗口背景色先显示),这是多 Activity 方案的固有代价;如果某些页面出现明显空白,请把现象告诉我。

## 十九、1.4.0(仅手机端):多服务器管理,一键切换

- **保存多台服务器**:每台一条记录(名称、地址、登录令牌、证书指纹、账号名),令牌仍用 Keystore 加密。「本地媒体」也是一条记录,和服务器一起切换。

- **各服务器数据分开**:浏览位置、播放进度按服务器分开存(文件夹 id 在不同服务器上可能重复);图片缓存本来就按地址区分。切换时聊天 / 搜索页会自动关闭,避免显示上一台的内容;切换前发出的请求若迟到收到 401,不会让新服务器掉线。
- **从旧版本升级**:原来的单服务器登录会自动变成第一条记录(令牌、指纹、浏览位置都保留),不需要重新登录。
- **这一版按用户要求没有做运行测试,只保证编译通过**。真机上要看的地方:旧版本升级后是否仍保持登录、侧边栏切换后列表是否刷新、添加第二台服务器时的指纹确认。

## 二十、服务端 1.2.0:扫描进度稳定显示 + 可只扫某一个盘

- **进度列表不再乱动**:以前服务端用 map 保存各盘的进度,遍历顺序是随机的,管理程序里的盘会来回换位置。现在固定按配置里根目录的顺序排列,而且服务一启动所有盘就都在列表里(位置固定),不是谁开始扫谁才出现。
- **速度稳定**:以前每秒取一次瞬时值再做指数平滑,而且元数据按"每 300 个一批"计数,所以"个/秒"长时间是 0、批完成时突然很大。现在(1)元数据读取改成每处理完一个文件就计数(照片按 30 张一小批给 exiftool);(2)速度 = 最近 10 秒窗口内的计数增量 / 窗口时长;(3)扫描 → 读取元数据切换、新一轮从 0 开始计数时清空窗口,不会出现负数或残留。预计剩余时间也因此更稳。
- **已读取数量不再是 0**:重启后复用旧索引时,进度原来是 0 个文件 / 0 个文件夹;现在启动时就用数据库里已有的数量初始化(后台查询,不拖慢启动),并显示上次完整扫描的时间。元数据进度的"已读"不会超过总数。
- **只扫描单个盘**:「总览 → 索引进度」里每个盘右侧多了「只扫这个盘」按钮(原来的按钮改名「全部重新扫描」)。服务端的管理接口 `POST /api/v1/admin/rescan` 本来就支持 `{"rootId":"N"}`,桌面端补上了参数;只重扫这个盘(丢弃它被中断的记录,从头完整扫一遍,再读元数据、预热封面),其它盘不受影响。盘正在扫描时按钮会置灰。
- **这一版按用户要求没有做运行测试,只保证编译通过并打包**。

## 二十一、服务端 1.2.1:更新后不再丢媒体根目录

- **原因**:配置文件原来放在程序目录里(`<程序目录>\runtime\mediahub\config.json`),装新版安装包 / 换一个便携版文件夹时,程序目录整个被替换,配置里的媒体根目录(以及端口、转码、TLS 等所有设置)就没了。数据库在 `C:\MediaHub\data`,一直是保留的,所以以前重新添加根目录时才能"复用已扫描的索引"。
- **现在配置固定放在 `C:\MediaHub\config.json`**(和数据目录同级,不在程序目录里),更新或换文件夹都不受影响。第一次运行新版时,管理程序会自动把旧位置的配置搬过来:先看当前程序目录里的,没有就找同级目录里名字以 `MediaHub` 开头的其它便携版文件夹和 `%LOCALAPPDATA%\MediaHub` 安装目录,取最近修改的一份。开发环境(设置了 `MEDIAHUB_ROOT`)仍用项目里的 `runtime\mediahub\config.json`。
- **兜底**:如果启动时配置里一个根目录都没有(例如这次之前的更新已经把配置弄丢了),服务端会按数据库里登记过的根目录恢复(优先恢复上次还处于启用状态的;已经被空配置停用的,在配置文件缺失时恢复所有路径仍然存在的),并写回配置文件,日志里会有一条"已按上次使用的恢复"。恢复后原有索引直接复用,不用重新扫描。
- 想改回别的位置:管理程序始终通过 `-config` 把配置路径传给服务端,不影响手动 `mediahub serve -config <路径>`。
- **这一版按用户要求没有做运行测试,只保证编译通过并打包**。

## 二十二、服务端 1.3.0 / 手机端 1.5.0:转码按码率、进度同步到服务器、右滑上一个

- **转码只调码率,不改分辨率**:服务端内置 ffmpeg 转码去掉了缩放滤镜(原来按"最大高度"缩小),视频始终保持原分辨率,只按码率压缩;Jellyfin 路径也不再传 `MaxHeight`。接口 `…/hls/master.m3u8?maxBitrate=…&sid=…`(`maxHeight` 参数不再识别)。手机端:设置「编解码器 → 服务端转码 → 转码码率」(自动 = 按原视频分辨率:480p 1.5M / 720p 3M / 1080p 6M / 1440p 12M / 2160p 20M,也可固定 2 ~ 40 Mbps),原来的"最大分辨率"设置删除;播放时「更多 → 画质 / 转码」里选 1.5 / 3 / 6 / 12 / 20 Mbps。
- **浏览记录和视频播放进度同步到服务器**:换一台设备打开同一个群聊,回到上次退出的位置(同样的排序、网格 / 聊天、列数、过滤),视频接着上次的进度。服务器数据库迁移 v7 新增 `user_view`、`user_playback` 两张表(按用户分开);接口 `GET/PUT /api/v1/dialogs/{id}/view`、`GET/PUT /api/v1/media/{id}/playback`、`DELETE /api/v1/state/views|playback`。以 `savedAt` 为准,后写的覆盖先写的。手机端打开群 / 视频时先问服务器(最多等 2~2.5 秒),没有记录或连不上就用本机保存的;滚动时 3 秒去抖同步,离开页面 / 退出视频时立即同步。「设置 → 存储与缓存 → 清除浏览位置 / 播放进度」会连服务器上的一起清。本地媒体模式不同步。位置是"某个媒体 + 像素偏移",不同尺寸的设备上偏移会有一点误差。
- **查看器右滑 = 上一个**:聊天流最新在底部,列表序号 0 是最新的,原来向右滑会去序号更小的(更新的、下面那条)。现在向右滑回到上面那条(更早的),向左滑到下面那条;「上一个 / 下一个」按钮和"播放完自动下一个"也按屏幕上的先后。设置「图片查看器 → 翻页 → 向右滑 = 上一个」可关闭(关闭后相反)。网格和搜索结果里本来序号小 = 靠前,行为不变。
- **管理程序索引进度里的文字居中**:状态徽标("扫描中 / 读取元数据 / 已完成")放进按钮组后被拉高、文字贴在上沿;现在徽标固定宽度、水平垂直居中,按钮内容也居中。
- **这一版按用户要求没有做运行测试,只保证编译通过并打包**。
