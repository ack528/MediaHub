## 3. 环境事实与约束(更新)

| 项 | 内容 | 影响 |
|---|---|---|
| CPU/GPU | i3-8100(4 核 4 线程,无超线程),核显 UHD 630 | 编码靠 QSV;软编只能顶 1 路 720p。UHD 630 无 AV1 硬解(按 Intel 规格,**PoC 确认**) |
| 磁盘 | C: 仅 33.5GB;D/E/L/M 剩余 56–244GB;**F/G/H 近乎 0**;I: 200GB、K: 339GB | 你说会清理。**启动自检**:某盘剩余 < 配额(50GB)时,该盘缓存自动回退到 `runtime\cache\<卷>\` 并告警 |
| 机械盘 | 2.72TB 级大概率为 HDD | 索引/封面按盘串行;原图直出时同一盘并发读取要限流 |
| 网络 | 仅局域网(Wi-Fi 为主) | 原图直出的带宽是主要风险,见下 |
| 使用方式 | 单人,≤2 台设备 | 简化全部并发设计 |

### 关键风险:"图片只用原图"在列表里会很吃带宽
一屏网格 20–30 张,若是 3–8MB 的手机/相机原图,首屏要拉 100–200MB;Wi-Fi 实测 25–50MB/s 时是 **2–8 秒**,硬盘上还是大量随机读。已做的缓解(不违背你的决定):
1. 客户端**降采样解码**(省内存,但不省流量);
2. 快速滑动不加载,**减速后才请求**;
3. 客户端把首次解码结果存为**本地小缩略图缓存**(手机本地 ~2GB,默认开),第二次浏览秒开、不再下载;
4. 提供一个**零存储**开关 `imageThumbMode = exif`:JPEG/HEIC 自带内嵌缩略图(约 10KB),服务端只读文件头部直接返回,不生成、不落盘;默认关闭。
Phase 0 会实测;如果体验不满意,打开第 4 条即可,无需改架构。

## 4. 架构一览

```
 Android(Local-TG)  ──HTTP/局域网──▶  MediaHub 网关(Go,Windows)
   Compose / Coil / Media3 / libmpv        ├ 索引器 → SQLite
                                           ├ 原图 Range 直出 · 视频封面 · 兜底格式转换
                                           ├ 播放决策:direct 自己出 / 其余委托 Jellyfin
                                           └ 每盘缓存 X:\.mediahub\(≤50GB)
                                                    │ 仅 127.0.0.1
                                           Jellyfin(便携版,仅转码,Intel QSV)
                                                    │
                                    C: D: E: F: G: H: I: K: L: M:(媒体)
```

```
本地浏览\
  docs\       本组文档
```

**发现(重要):**
1. **Android 17(API 37)访问局域网需要 `ACCESS_LOCAL_NETWORK` 运行时权限**。不声明时应用连不上 `10.0.2.2` / `192.168.x.x`,只会表现为"无法连接"。已在 Manifest 声明并在启动时弹窗申请(系统文案是"附近设备")。**真机首次安装必须点"允许"。**
2. 模拟器自带的硬解码器(goldfish)运行时会失败;已加软解回退,真机上遇到个别硬件解码器问题也能自救。
3. **HEIC/HEIF 在 Android 上不可靠**:诺基亚 HEIF 显示方向不对(旋转信息未应用),libheif 示例 HEIC 解码失败(头像空白)。→ 需要服务端 `render`(libvips 转 JPEG,已验证能解这些文件)作为客户端解码失败时的自动回退,这是下一步。
4. 项目路径含中文:需要 `android.overridePathCheck=true`(已设),构建正常。
5. Android 17 系统会弹出"手写笔教程"(`stylus`)对话框,自动化测试时需要取消,与应用无关。
