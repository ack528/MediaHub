## 一、从 Material Motion 源码里读到的数值

| 项目 | 数值 | 出处 |
| --- | --- | --- |
| 共享轴(X / Y)时长 | 450ms(`motionDurationLong1`) | `MaterialSharedAxis.java` |
| 共享轴滑动距离 | 30dp | `transition/res/values/dimens.xml` |
| 共享轴缓动 | Emphasized:`M 0,0 C 0.05,0 0.133333,0.06 0.166666,0.4 C 0.208333,0.82 0.25,1 1,1` | `motion/res/values/tokens.xml` |
| 淡入淡出穿越(Fade Through)起始缩放 | 0.92,时长 450ms | `MaterialFadeThrough.java` |
| 淡入淡出穿越的分界 | 进度 35%:旧页在前 35% 淡出,新页在 35% 之后淡入 | `FadeThroughProvider.java` |
| Fade(出现 / 消失)| 出现 400ms、起始缩放 0.8、强调减速;消失 150ms、强调加速 | `MaterialFade.java` |
| Emphasized 减速 / 加速 | `cubic-bezier(0.1,0.7,0.1,1)` / `cubic-bezier(0.3,0,0.8,0.2)` | `tokens.xml` |
| Standard | `cubic-bezier(0.2,0,0,1)` | `tokens.xml` |

要点:共享轴里旧页先消失、新页后出现,两页同时可见的时间很短,所以不会糊在一起。

## 二、从文档里学到、并且已经用上的做法

1. 转场由系统调度,能交给系统的交给系统:页面之间是 Activity,默认用系统转场和跨 Activity 的预测性返回(`enableOnBackInvokedCallback` 已开)。
2. 跟手:返回用 `PredictiveBackHandler`,拿到进度驱动缩放;手势取消时用弹簧回到初始值。查看器(Hero.kt)早就这么做;3.4.0 起文件夹内搜索面板也是。
3. 全屏界面返回时,内部区域随手势进度缩小(搜索面板:缩到 90%、变淡、露出圆角)。
4. 弹簧收尾、可打断:打开用弹簧(ζ≈1.2),取消返回手势用弹簧回弹,动画中随时可以接着动。
5. 不要重复接管系统已经做好的返回:Material3 1.4.0 的 `ModalNavigationDrawer` 自带抽屉的预测性返回(类 `DrawerPredictiveBackState`);主界面以前自己加了 `BackHandler`,把它盖掉了,只剩"松手就关"。3.4.0 去掉。

## 三、整个软件的界面切换逐项检查

| 切换 | 做法 | 3.4.0 的处理 |
| --- | --- | --- |
| 主界面 ↔ 文件夹 / 设置 / 搜索 / 随机页(Activity) | 设置里「界面动画」:系统风格(默认,系统转场 + 预测性返回)/ 整屏滑动 / Material 共享轴 / 淡入淡出 / 关闭 | 共享轴改成源码里的数值:滑动约 8% 屏宽(30dp)、450ms、完整 Emphasized 曲线,旧页前 90ms 淡出、新页 80ms 后淡入;淡入淡出改成 Fade Through(旧页 90ms 淡出,新页延迟 90ms 淡入 + 从 92% 放大)。系统风格不变 |
| 缩略图 ↔ 全屏查看器 | Hero.kt:点哪里从哪里展开、拖拽关闭、预测性返回、可打断 | 不变(已按 B 站 / 小红书逐帧测量做过,见 docs/14) |
| 文件夹内搜索 | 顶栏淡入淡出换成输入框;结果面板淡入上滑;选中后等列表定位完再淡出 | 加预测性返回:面板跟手缩小 / 变淡,取消弹回 |
| 主界面侧边栏 | Material3 ModalNavigationDrawer | 去掉盖住预测性返回的 BackHandler,抽屉跟着手势缩回 |
| 登录页 ↔ 列表 | Fade Through(旧页 90ms 淡出,新页 90ms 后淡入 + 0.92 缩放) | 不变(和源码一致) |
| 聊天流 / 网格 / 瀑布流切换 | AnimatedContent:淡入 + 0.96 缩放 | 不变 |
| 登录页两步之间、错误提示 | 弹簧滑入 / 展开 | 不变 |
