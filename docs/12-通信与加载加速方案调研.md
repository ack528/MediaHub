# 通信与加载加速方案调研(3.0.0)

> 2026-10 的调研:服务器 ↔ 手机之间的通信、图片 / 视频加载,有哪些开源方案或通用做法能提速,哪些集成进了 3.0.0,哪些没有集成以及原因。
> 标「实测」的是在本项目里真的跑过的;其余来自公开文档,没有在本项目里验证。

## 已集成

| 方案 | 做法 | 解决什么 |
|---|---|---|
| 响应压缩(gzip) | 服务端 `gzip.go`:JSON 接口和 HLS 播放列表在客户端接受 gzip 时压缩;OkHttp 自动带 `Accept-Encoding` 并透明解压 | 群组列表 / 历史 / 搜索的 JSON 压缩后约为原来的 1/5 ~ 1/10,云中继 / 移动网络下首屏更快(单元测试验证压缩与解压一致) |
| 服务端 WebP 缩略图 | `render?fmt=webp`:ffmpeg(libwebp)按 240 / 360 / 480 / 720 / 960 / 1440 档位生成,缓存在各盘 `.mediahub\thumb<档位>`,`immutable` 缓存头;手机只对原图明显更大的静态位图使用,失败退回原图 | 以前 jpg / png / webp 的小图是直接下载**原文件**再在手机上缩小,一张 5 MB 的照片只为显示一个小格子;现在只要几十 KB(实测 1600×1200 的图 → 240 档 WebP 不到原图的 1/4) |
| 转码预热 | `POST /media/{id}/hls/prepare`:手机在看当前视频时,服务端提前转好相邻视频的前 3 段(≈12 秒);不挤掉别人正在播放的转码,转够自动停 | 切到下一个视频时第一段已经在磁盘上,几乎秒开(测试验证预热后第一段秒回) |
| 播放偏好同步 | `GET / PUT /state/player`:服务端按用户记住转码码率和编码,手机没带参数时服务端按它转;手机直接沿用上一个视频的选择 | 少一次手动选择、少一次"先试原画失败再转码"的往返 |
| 连接预热 | 登录 / 切服务器 / 切网络后立刻请求 `/server/info`(同时取能力 `caps`),TLS + HTTP/2 连接提前建好 | 第一次浏览不用再等握手(云中继上握手可达几百毫秒) |
| 能力声明 | `/server/info.caps`:转码编码、QSV、码率上限、各功能是否支持 | 手机据此显示选项,旧服务端自动退回原行为 |
| H.265 转码 | `hevc_qsv`(启动时真编一帧确认),HLS 仍用 MPEG-TS 封装(ExoPlayer 支持 TS 里的 HEVC);失败退回 H.264 | 相同码率画质更好 / 相同画质省 30% ~ 50% 流量(实测软编 libx265 输出正确) |
| DoH + 最优 IP | 并发问多个 DoH(哪个先答用哪个),同一域名多个 IP 时按 TCP 连接耗时排序 | 访问 GitHub 时避开被污染的系统 DNS、选最近的地址(借鉴 Watt Toolkit 的"同一个域名选最近的地址"思路) |
| 镜像并发探测 | 直连 + 8 个镜像同时发 1 字节 Range 请求,先响应的先下;界面显示每个源的延迟和是否真的返回文件 | 更新下载更快更稳 |

## 没有集成(以及原因)

| 方案 | 为什么没做 |
|---|---|
| HTTP/3(QUIC)/ Cronet | 需要引入 Cronet(约 +5 MB 或依赖 Play 服务)并且 NAS 端要有 QUIC 服务;很多云中继 / 运营商对 UDP 限速或阻断,收益不确定。当前 HTTP/2 + 10 秒 PING 保活已经解决了断连问题。以后可以在测速页加"UDP 可用性"探测后再决定 |
| Brotli / zstd 压缩 | 比 gzip 再小 10% ~ 20%,但 Go 标准库没有,要引第三方包;JSON 本来就不大,收益有限 |
| AVIF / JPEG XL 缩略图 | 比 WebP 更小,但 ffmpeg 编码很慢(AVIF)或手机解码支持不全;WebP 是速度、体积、兼容性的折中 |
| Media3 `DefaultPreloadManager` | 官方的下一个视频预加载。我们的视频是 PagerScreen 里每页一个播放器 + 服务端转码,预热放在服务端(转码)更有效;直连播放的预加载可以以后用它做 |
| 在 NAS 上预生成全部缩略图 | 十万级照片库预生成要很久、占缓存配额;改成按需生成 + 缓存更合适。想要的话可以在扫描后给最近的 N 张预热 |
| TCP BBR / 内核调优 | 在 Windows NAS 上不适用 |

## 参考

- Watt Toolkit(BeyondDimension/SteamTools,GPL-3.0):本地反向代理 + 域名加速。公开页面没写清 DoH 细节,本项目只借鉴了"同一域名选最近的 IP"和多 DNS 的思路,没有复用它的代码
- DoH JSON 接口:alidns、doh.pub、Cloudflare、Google、AdGuard、dns.sb 都支持 `?name=&type=A`(路径不同:`/resolve` 或 `/dns-query`)
- Czkawka(重复文件):感知哈希 + 汉明距离的思路;VidDup:视频多帧哈希。本项目自己实现(dHash + 多索引哈希找候选),没有引入它们的代码
- Media3 预加载:`DefaultPreloadManager`、`PreloadConfiguration`
