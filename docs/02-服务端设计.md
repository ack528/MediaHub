# 02 · 服务端设计(MediaHub 网关 + Jellyfin 转码)

> 前提:局域网、单人、≤2 台设备、i3-8100 + UHD 630(无独显)、图片只用原图、视频有封面、每盘缓存 ≤50GB。

## 1. 组成

| 组件 | 作用 | 形态 |
|---|---|---|
| **MediaHub 网关** | 索引、对话/历史 API、登录、原图/视频直出、视频封面、兜底格式转换、播放决策、Jellyfin 代理 | Go 单文件 exe(用任务计划程序开机自启),监听局域网地址 |
| **Jellyfin(便携版)** | 只负责视频 remux/转码(Intel QSV)与字幕提取 | 仅监听 127.0.0.1 |
| ffmpeg / ffprobe | 视频探测、封面抽帧;Jellyfin 自带一份 jellyfin-ffmpeg | 便携,位于 `tools\` |
| ExifTool | 照片 EXIF 时间/尺寸/方向、RAW 内嵌预览 | 便携 |
| libvips(CLI) | 仅用于"客户端解不了的图片格式"的兜底转换(RAW 优先走 ExifTool 内嵌预览;手机是 Android 17,HEIC/AVIF 原生可解,基本只剩 TIFF/JXL/PSD 等冷门格式) | 便携,可选 |
| SQLite | 索引库(WAL + FTS5) | 单文件 |

语言:**Go**。理由:标准库自带 HTTP 与 Range(`http.ServeContent`)、反向代理(`httputil.ReverseProxy`,可无缓冲透传);`golang.org/x/sys/windows` 取 NTFS 文件 ID 与目录监听;纯 Go SQLite(`modernc.org/sqlite`,**已验证 WAL + FTS5 trigram 可用**,无需 cgo/C 编译器);单个 exe,编译秒级,`go test` 自带;便携包仅 ~270MB。

## 2. 目录与配置

```
runtime\
  jellyfin\{data,config,cache,log,transcode}    Jellyfin 便携运行目录
  mediahub\config.json                           网关配置
C:\MediaHub\data\{hub.sqlite,logs\}              索引库与日志(放 C: 固态;C: 可用 < 10GB 时告警)
  cache\<卷标>\                                  缓存自检回退目录(仅当该盘空间不足)
X:\.mediahub\{posters,renders}\.ignore           各媒体盘上的缓存(≤ 配额)
```
`config.json`(示例):
```json
{
  "listen": "http://0.0.0.0:8480",
  "dataDir": "C:\MediaHub\data",
  "roots": [
    { "path": "D:\\", "label": "D:" }, { "path": "E:\\" }, { "path": "F:\\" }
  ],
  "exclude": ["$RECYCLE.BIN", "System Volume Information", ".mediahub", "@eaDir", "Thumbs.db"],
  "cache": { "perDriveQuotaGB": 50, "fallbackDir": "runtime\\cache" },
  "images": { "mode": "original", "thumbMode": "off|exif", "fallbackConvert": true },
  "video": { "engine": "jellyfin", "maxTranscodes": 2, "hwaccel": "qsv", "softwareFallback": true },
  "jellyfin": { "url": "http://127.0.0.1:8096", "apiKey": "<dashboard 生成>" },
  "auth": { "tokenDays": 180 }
}
```
- 登录账号用命令创建:`mediahub user add <name>`(交互输入密码,存 PBKDF2 哈希)。最多 2 个账号即可。
- 启动时记录每个根目录的**卷 GUID**,之后按 GUID 识别,盘符变化不影响。

## 3. 索引器

### 3.1 对话规则
- 直接含媒体文件(图片/视频/GIF/音频)的文件夹 = 一个对话;只含子文件夹的 = "话题容器"(点进去先列子文件夹)。
- 子文件夹默认作为"话题";每个对话可切换"包含子文件夹(递归)"。
- 排除:`$RECYCLE.BIN`、`System Volume Information`、`.mediahub`、`@eaDir`、`Thumbs.db` 及自定义。
- 文件类别:先按扩展名,再用文件头魔数校正;未知归入 `file`。

### 3.2 扫描分三阶段(用户不必等全库完成)
1. **文件系统级**:名称、大小、mtime/ctime、文件 ID。每个根一条遍历线程;用 `FindFirstFileEx(FIND_FIRST_EX_LARGE_FETCH, FindExInfoBasic)` 批量读取。完成后对话列表即可使用。
2. **元数据**:照片用 ExifTool(`-stay_open` 常驻进程批量读,只读文件头)取拍摄时间、尺寸、方向;视频用 ffprobe 取编码/时长/码率,并缓存 `probe_json` 供播放决策。
3. **视频封面**:按需生成(用户滚到才生成),夜间可选预热最近的对话。
- **增量**:`ReadDirectoryChangesW` 监听(去抖 2 秒)+ 每日一次轻量校对。
- **稳定 ID**:`hash64(卷GUID, NTFS 文件ID)`,改名、移动后不变;取不到时回退到路径哈希。
- 个人使用场景下**不做 USN 日志**;若全库扫描太慢再考虑。

## 4. 图片:只用原图

### 4.1 原则
- **列表、聊天流、查看器都直接请求原文件** `GET /media/{id}/file`(支持 Range)。
- 客户端在请求 `playback`/`caps` 时声明自己"能解码的图片格式"(启动时用 `ImageDecoder`/`BitmapFactory` 实测:JPEG、PNG、WebP、GIF、BMP 必有;HEIC、AVIF 看系统版本)。
- 服务端根据格式决定:**能解码 → 原图;不能 → `render` 兜底转换**。

### 4.2 兜底转换(`/media/{id}/render?max=4096`)
| 源格式 | 方法 | 输出 |
|---|---|---|
| RAW(CR2/CR3/NEF/ARW/DNG/ORF/RAF…) | ExifTool 取内嵌预览,**三种都试(`-PreviewImage`、`-JpgFromRaw`、`-OtherImage`)并取最大的一张**。实测:佳能 CR3 1620×1080、索尼 ARW 1616×1080、苹果 DNG 4032×3024,但**尼康 Z6 的 `PreviewImage` 只有 640×424**,需用更大的 `JpgFromRaw`。vips(libraw)也能完整解码四种 RAW,但慢,仅作回退 | 内嵌 JPEG 原样输出 |
| HEIC/AVIF(仅旧手机需要) | libvips + libheif:**已用真实 iPhone / 诺基亚 / libheif 示例 HEIC 与 AVIF 验证可解码**(之前对 HEIC 的担心不成立) | JPEG q90,长边 ≤4096 |
| TIFF / JXL / PSD / SVG / BMP 变体等 | libvips;PSD 等冷门格式仍失败则 ffmpeg 单帧 | JPEG/WebP |
| 全部失败 | 返回通用图标并标记 `corrupt` | — |
- 转换结果存入**该盘**的 `renders\`,计入 50GB 配额(LRU);重复访问直接命中。
- 这是仅有的"服务端处理图片"路径,**常见格式永远走原图**。

### 4.3 零存储缩略图开关 `thumbMode=exif`(默认关)
JPEG 的 EXIF 与 HEIC 中常带约 160×120 的内嵌缩略图。开启后 `GET /media/{id}/thumb` 只读文件头(~64KB)取出并返回,**不生成、不落盘**,对机械盘也友好。无内嵌图的格式返回 404,客户端回落到原图。用于网格首屏提速,是否开启由 Phase 0 实测决定。

### 4.4 GIF
原样下发(Coil 有 GIF 解码)。超大 GIF 若卡顿,后续可加"GIF→MP4"的按需转换,MVP 不做。

## 5. 视频

### 5.1 硬件事实(i3-8100 / UHD 630)
| 能力 | 状态 | 备注 |
|---|---|---|
| H.264 硬编/硬解 | ✔ | QSV 主力 |
| HEVC 8/10bit 硬解 | ✔ | HDR10 源可解 |
| HEVC 硬编 | 核显支持,但**输出统一用 H.264**(手机兼容最好) | |
| VP9 硬解 | ✔ | |
| **AV1 硬解** | ✘(按 Intel 规格) | AV1 源只能软解,i3-8100 对 4K AV1 会吃力;优先让手机直放 AV1(若手机支持硬解) |
| HDR→SDR 色调映射 | 需 OpenCL(核显驱动自带);**PoC 确认**是否可用 | 不可用则 HDR 源只做直放 |
| 软编兜底 | libx264 veryfast | 4 核无超线程,仅 1 路 ≤720p |
- **服务器必须启用核显**:部分主板在没接显示器时会关闭核显;如 `ffmpeg -init_hw_device qsv` 失败,到 BIOS 里打开 iGPU(或接显示器/假负载)。这是 PoC 第一天的检查项。

### 5.2 播放决策(网关内)
```
caps(手机):容器 / 视频编码+档次+分辨率 / 音频编码 / 最大码率
网络:局域网(默认不限速);用户在播放器里选"清晰度":自动 / 原画 / 1080p / 720p / 480p

容器、视频、音频都在 caps 内、且不超过所选上限      → direct   网关 Range 读原文件(不占 CPU)
视频可直接用,仅容器/音频不支持(mkv→fMP4、DTS→AAC)  → remux    视频 copy,音频转 AAC(CPU 几乎为 0)
其余(编码/分辨率/HDR/所选清晰度需要降档)             → transcode QSV H.264 + AAC,按所选档位
```
- 默认"自动" = 能直放就直放;局域网下绝大多数视频走 direct/remux。
- 清晰度菜单对应的目标码率(可调):1080p ≈ 6 Mbps、720p ≈ 3 Mbps、480p ≈ 1.2 Mbps。切换清晰度 = 以当前进度重开一个会话(简单可靠;不做自适应码率)。
- 播放器报错 → `POST /playback/{id}/error`,网关排除该方案重判(direct→remux→transcode),仍失败再提示用 mpv。

### 5.3 Jellyfin 委托(仅 remux/transcode)
```
POST /media/{id}/playback
  → 网关把 caps 转成 Jellyfin DeviceProfile,
    POST {jf}/Items/{jfId}/PlaybackInfo { DeviceProfile, MaxStreamingBitrate, StartTimeTicks, AudioStreamIndex … }
  → 取回 TranscodingUrl,改写为网关代理路径 /jf/{一次性令牌}/… 返回给客户端
客户端 → 网关 /jf/… → (带 API Key)Jellyfin → HLS m3u8 与分片 → 流式透传(支持 Range,不缓冲)
结束 → DELETE /playback/{id} → 向 Jellyfin 请求停止对应转码
```
- 条目映射:定期 `GET {jf}/Items?Recursive=true&IncludeItemTypes=Video&Fields=Path` 建立 `路径→jfItemId`(写入 `media.jf_item_id`)。映射不到的视频只能直放。
- Jellyfin 的 HLS 播放列表若为相对路径,前缀代理即可;若含绝对地址/`api_key`,网关代理时重写(**PoC 验证**)。
- 字幕:文本字幕经代理取 WebVTT;ASS 样式字幕建议用 mpv 播放。

### 5.4 Jellyfin(便携版)设置清单
| 项 | 值 |
|---|---|
| 启动参数 | 指定 `--datadir/--configdir/--cachedir/--logdir` 到 `runtime\jellyfin\…`,`--ffmpeg` 指向 `tools\` 中的 jellyfin-ffmpeg(参数名以实际版本为准,**PoC 核对**) |
| 监听 | 仅 `127.0.0.1:8096` |
| 库 | Home Videos and Photos,路径指向各视频所在盘;**关闭**实时监控,扫描只在夜间计划任务;**关闭**章节图/trickplay/图片提取/元数据下载/NFO |
| 硬件加速 | Intel QuickSync (QSV),启用硬件解码(H.264/HEVC/VP9)和 HEVC 10bit,色调映射看 PoC |
| 转码 | 同时转码上限 2;转码临时目录 `runtime\jellyfin\transcode` |
| 忽略缓存目录 | 各盘 `.mediahub\` 内放空的 `.ignore` 文件,避免 Jellyfin 把缓存里的 WebP 当媒体(**PoC 验证**) |
| 访问 | 仅用 API Key;管理界面只在服务器本机打开 |

### 5.5 视频封面
- `ffmpeg -ss <时长10%> -i <文件> -frames:v 1 -vf scale=640:-2 → WebP q75`,约 15–35KB;黑帧检测失败则改取 25% 处;HDR 源做简单色调映射。
- 存放 `X:\.mediahub\posters\{id低2位hex}\{id}.webp`(X = 视频所在盘),响应带 `ETag` 与长缓存。
- 只有 1 档(640 宽);同时提供 `thumbhash`(几十字节)内联在列表里,滚动时先显示模糊图。
- 并发:每盘同一时刻 1 个抽帧作业(机械盘友好),全局 2 个。
- **进度条预览图(sprite)**:MVP 不做;需要时按需生成 1 帧/10 秒、10×10 拼图,计入配额。

## 6. 每盘缓存策略(新)

| 项 | 规则 |
|---|---|
| 位置 | 视频所在盘的 `X:\.mediahub\`(隐藏+系统属性),内含 `posters\`、`renders\`、`.ignore` |
| 配额 | 每盘 50GB(`perDriveQuotaGB`),超出按最久未访问(LRU)淘汰 |
| 自检 | 启动时检查每盘可用空间:`可用 < 配额 + 5GB` → 该盘缓存回退到 `runtime\cache\<卷>\` 并在日志与管理接口告警。你清理出空间后重启即自动使用盘内缓存 |
| 写入边界 | 代码里只有一个 `CacheWriter`,路径必须在上述目录内,单元测试断言"绝不写入其它路径"。其余一切对媒体盘只读 |
| 原子性 | 先写 `.tmp` 再重命名,崩溃不留半成品;启动时清理 `.tmp` |
| 盘离线 | 对应缓存条目暂不可用,不影响其它盘;盘重新上线后缓存继续有效 |
| 外部可见性 | 缓存目录在索引时被排除;Jellyfin 靠 `.ignore` 排除 |

## 7. 认证与安全(局域网版)
- `POST /auth/login` 用户名+密码 → **长期令牌**(默认 180 天,滑动续期),服务端仅存令牌哈希;`POST /auth/logout` 作废。
- 密码:PBKDF2-SHA256(`golang.org/x/crypto/pbkdf2` 或标准库 `crypto/pbkdf2`),足够。登录失败做简单延迟(如 1 秒)。
- 监听局域网地址;Windows 防火墙规则仅限"专用网络"配置文件;Jellyfin 只监听回环。
- 明文 HTTP:局域网内接受;将来想加 HTTPS 只需在网关挂证书。
- **API 不接受任何文件路径**,只接受 ID;打开文件前校验路径仍在根目录内(防 `..`、联接点);文件以只读共享读方式打开。
- 子进程(ffmpeg、ExifTool、vips)参数用数组传递,不拼 shell 字符串,有超时和内存上限。
- 已接受的风险:解码器(libheif、ffmpeg)处理任意文件时未做进程沙箱;个人环境下可接受,保持工具版本更新即可。

## 8. 运行与运维
- `runtime\start-all.ps1` 启动 Jellyfin 与 MediaHub,`stop-all.ps1` 停止;开机自启用 Windows **任务计划程序**("系统启动时"触发,无需服务化),需要时再升级为 Windows 服务。
- 日志:`C:\MediaHub\data\logs\`(按天滚动,总量上限 1GB),关键指标:索引进度、各盘缓存占用与回退告警、转码并发数、ffmpeg 失败率。
- 备份:`hub.sqlite`、`config.json`、Jellyfin 的 `config`;缓存可丢弃。
- 管理接口:`GET /admin/status`(索引进度、缓存占用、Jellyfin 连通性、QSV 自检结果)。

## 9. 风险清单

| 风险 | 对策 |
|---|---|
| 核显在无显示器时被禁用,QSV 不可用 | PoC 第一天验证;BIOS 打开 iGPU 或接假负载/显示器 |
| i3-8100 软解 AV1/软编吃力 | 优先直放;AV1 手机不能解时给出明确提示而不是卡死;限制并发 2 |
| 原图直出让列表首屏慢 | 本地缩略图缓存 + 减速后加载;必要时开 `thumbMode=exif` |
| 路径→jfItemId 映射漂移 | 卷 GUID/文件 ID 稳定;定时校正;映射缺失降级为直放 |
| F/G/H 空间未清理 | 启动自检回退到 `runtime\cache\`,不会写满 |
| Jellyfin 升级改变 API | 固定版本;升级前用样本回归 |
