# 可复用到其他项目的做法

> 从「本地浏览」(Go 服务端 + Tauri 桌面管理程序 + Android 客户端)里,按提出的修改点整理。一个点一行:做法 + 原因。

## 网络与稳定性

- 接口和图片 / 视频各用独立的 OkHttp 客户端(各自的连接池和调度器),大文件把连接占满时接口请求不会排队。
- HTTP/2 每 10 秒 PING 保活,死连接几秒内发现并断开,不用等系统超时。
- 监听 `ConnectivityManager`:断网时请求先等网络恢复,Wi-Fi ↔ 移动数据切换时清理旧连接并取消卡住的请求。
- 幂等请求(GET / PUT / DELETE)网络失败自动重试 3 次,间隔很短;POST 不重试,避免重复提交。
- DNS 解析失败时退回上次解析成功的地址,云服务器域名偶发解析失败就不会卡住。
- 播放器遇到网络中断用 `LoadErrorHandlingPolicy` 加大重试次数并自动恢复,几十秒内恢复就不弹"播放错误"。
- 局域网 / 私有服务用自签名证书,客户端固定证书指纹,不需要公网证书也不怕中间人。
- 访问 GitHub 的更新逻辑:DoH 优先(系统 DNS 可能返回被污染的地址而不报错),DoH 服务器自己用固定 IP 连接避免鸡生蛋问题。
- 多个镜像 + 直连同时发 `Range: bytes=0-0` 探测,谁先返回 200 / 206 就用谁,其余取消;全部失败再按顺序回退。
- 镜像只负责搬字节:校验和文件优先直连获取,下载的包必须与之一致才使用,镜像不能决定"正确的 hash"。
- GitHub API 匿名限流(403)时,改用 `releases/latest` 的 302 跳转取 tag,再读 `SHA256SUMS.txt`,不依赖 API。
- 服务端对手机的浏览位置 / 播放进度这类高频写入"先应答再写库"(write-behind),不被扫描占着的写锁拖慢。

## 自动更新与发布

- 服务端自动更新:下载 → 校验 SHA-256 → 脚本等主进程退出 → 备份 → robocopy 覆盖 → 启动 → 45 秒健康检查 → 失败自动回滚。
- 更新脚本要在覆盖前等进程真正退出、杀掉管理程序,并保留私有目录(配置、数据、私有 DLL),否则更新会丢东西。
- 发布脚本直接用 `git credential fill` 取已保存的令牌调 GitHub API,不另存令牌、不打印;同名 tag 先删后建,便于重发。
- 公开仓库的发布包必须与个人使用包分开:脚本里断言发布目录没有版权文件(DLL),并在打包后检查 zip / APK 内容。
- 个人版带的私有文件首次启动复制到应用私有目录并一直保留,之后通过云更新装上不含它的发布版也不丢。
- `CHANGELOG.md` 是更新说明的唯一来源:打包时同步进应用资源,发布时截取最新条目写进 Release,应用里「更新说明」读同一份。
- 客户端和服务端各自一套版本号;发布前先看线上已有的最新版本号再取新号,避免和别人 / 别的会话的发布撞号或倒序(这次 2.11.0 就错在这里)。
- 发布后用线上的 `SHA256SUMS.txt` 和本地对比,确认上传没有损坏;GitHub 推送偶发 500 时后台循环重试,别重复改代码。

## 构建与工程化

- 所有工具链(JDK、Gradle、Android SDK、Go、Node、Rust、ffmpeg)放项目 `tools\` 目录,一个 `env.ps1` 设好环境,不依赖全局安装。
- Windows 路径含中文会让 CMake / Ninja 编译原生库失败:用 `subst` 把项目根映射成盘符再构建。
- 打包脚本参数化(`-Version`、`-Release`、`-SkipAndroid`、`-SkipDesktop`、`-SkipTests`),同一个脚本既出个人版又出发布版。
- 构建报链接器 / 进程初始化错误(如 `0xc0000142`)先判断是不是会话中断造成的,直接重跑,不要先改代码。
- `.gitignore` 默认排除签名密钥、版权文件、运行时数据、日志、测试数据和工具链;凭据不回显、不入库。
- 每次改动在文档里按"原因 → 做法 → 限制"写一节,日后排查和复用都靠它。

## 服务端与数据

- SQLite 开 WAL,`busy_timeout` 设到 60 秒,连接池放大;后台扫描和前台读写不会互相卡死。
- 扫描任务要有错误状态 + 自动重试、单个目录读取超时、停滞提示(显示卡在哪个目录),不能默默卡住。
- 大表"随机取"不用 `ORDER BY RANDOM()`:在 id 范围里随机取点,每点取 `id >= 点` 的第一条符合条件的,主键索引查找。
- 随机取点的条件列加一元加(`+m.type`),禁止 SQLite 选这些列上的索引再全量排序。
- 带条件的 `MIN / MAX` 会扫全表,边界要启动时就算好缓存,定期刷新,请求只查缓存。
- 启动时后台预热:预先算好范围、预先生成多份确定性的随机序列并读热数据库页,第一次请求不用等冷读盘。
- 固定随机序列:序列由(盐、范围、类型、槽位、批号)确定性生成,同一个 seed 永远是同一批;换盐 = 全部重新生成,盐存数据库里重启不变。
- 单次请求设时间预算(如 4 秒),到点有多少返回多少,不要让客户端等到超时。
- 加一张通用键值表 `kv(k, v)` 存小型服务端配置(例如随机序列的盐),不必每次都新建表。
- 新接口的参数要校验(类型、数字、范围),并配套单元测试覆盖"同参数稳定、换参数不同、非法参数 400"。

## Android 客户端

- 列表状态放 `ViewModel`(跟导航栈上这一页走),从全屏查看器返回时列表还在;只放 `remember` 会在返回后重建并回到顶部。
- 查看器每翻一页把"当前条目"写进共享状态,返回后列表只在该条目不可见时才滚过去,可见就不动,避免跳动。
- 协程里的 `CancellationException` 要重新抛出,不能当错误;并用代次计数,旧请求被取消后不能改新请求的状态(否则新请求被误判为"正在加载")。
- 强制高刷新率:窗口 `preferredDisplayModeId` + `preferredRefreshRate`,Android 15+ 再设根 View 的 `requestedFrameRate`;回到前台和显示模式变化时重新套用。
- 同分辨率下找刷新率 ≥ 120 的最高显示模式;没有这样的模式就不起作用,不要硬设。
- 手势阈值做成设置项(单位 dp),并选合理默认;用户反馈"太长 / 太短"时可以自己调。
- 加载超过 3 秒才显示下载速度和预计剩余时间,正常加载不打扰。
- 设置全部集中在一个 `AppSettings` 数据类 + DataStore(JSON),新增字段都给默认值,旧数据自动兼容。
- 应用内日志、崩溃报告、一键打包日志 zip:用户在真机上复现后把日志发回来就能定位,比远程描述有效得多。
- 同一套界面支持两种数据源:本地媒体模式用 OkHttp 拦截器伪装服务端接口(包括新增的 `random`、`reset`),界面代码不用分叉。
- 本地媒体库只在真的变化时才重读,并发请求共用一次读取,缩略图解码限流,避免大图同时解码撑爆堆。
- 特殊"群组"(置顶的虚拟入口)和普通条目用同一种行样式,点开才进入专用页面;侧边栏入口留给"操作类"功能(例如重新生成序列)。

## 图形与补帧(Vulkan / GL)

- 能力检测 + 分级降级:先试 FP16 着色器,失败自动退回 FP32;质量阶梯依次降光流精度、减半生成倍数、降输入分辨率。
- 某类 GPU 驱动的 bug(例如 Mali 对带纹素偏移的采样算错)用真值测试片段验证,再在加载着色器时统一换算进采样坐标绕开。
- 上屏节奏用真实的 vsync 间隔做相位累加,不要假设固定 60 / 120;屏幕短暂降频时保留会话几秒,不要每次重建。
- 补帧倍率按"60Hz 和 120Hz 下都规则"来选,并以视频声明的帧率为准,避免解码吃力时倍率乱跳。

## 与 AI 协作的方式

- 约定"AI 只编译,我来真机测试,日志放固定目录",让每轮反馈都带可定位的日志。
- 一个需求拆成"问题日志 → 根因 → 修复 → 新版本发布"的闭环,版本号和更新说明同步写好。
- 破坏性操作(删除目录、删除已发布的 Release)先列清单、等明确确认再执行,自己发错的东西可以直接更正,但要说明。
