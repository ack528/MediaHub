# 天玑 GPU 补帧适配检测(2026-10-08)

设备:vivo V2502A,天玑 9500(MT6993),Mali-G1-Ultra MC12,Vulkan 1.3.305,驱动 v1.r54p1,Android 17。
工具:`probe\`(天玑GPU检测 0.1/0.2,说明见 probe/README.md);原始日志在 `bugs\probe1`、`bugs\probe2`(不入库)。

## 结论
1. **LSFG 能在这块 GPU 上正常运行**:16 个配置全部通过,输出画面经与前后帧均值比对判定正常,没有设备丢失 / 崩溃 / 全黑。
2. 驱动能力齐全:`shaderFloat16`、`vulkanMemoryModel`、`storageImageExtendedFormats`、AHB 扩展、同步 2 / 时间线信号量全部具备;GL ↔ AHB 互通正确。**不需要换驱动**。
3. 性能(1080p,FP16):3.1 光流 30% 58ms / 40% 33ms / 50% 24ms / 75% 21ms / 100% 17ms;3.1P 35% 17ms / 50% 14ms / 75% 13ms。720p 3.1P 50% 13ms。
   - **光流精度越低越慢**(Mali 上小尺寸中间层利用率差)。主程序自动降级曾一路降到 25%,是跟不上的主因之一。
   - FP16 比 FP32 快 2.5 ~ 3 倍(720p:22ms 对 57ms);DXBC 路径最慢(540p 133ms)。
4. 真实节奏(按源帧率间隔送帧)下无降频:1080p 3.1P 50% 30fps 源 → 0% 超预算;720p 3.1P 50% 60fps 源 → 0% 超预算。1080p 3.1 标准模式 30fps 源有 9.8% 帧超预算;×3 生成(45.9ms)全部超预算。
5. 微基准:FP32 ≈ 1.3 TFLOPS,FP16 ≈ 3.5 TFLOPS,缓冲带宽 ≈ 64GB/s,单次提交 0.12ms,派发+屏障 3.6µs。2560x1440 3.1 50% 要 53ms,不可用。

## 主程序据此的改动(2.11.0)
- `Lsfg.deviceSupported` 不再按处理器厂商禁用。
- 自动降级的光流精度档位只到 50%。
- 推荐:Mali 上用 FP16(默认)+ 性能模式(3.1P)+ 光流 50%。

## 2026-10-08 下午:重影 / 扭曲的根因(已修复,主程序 2.12.0)

### 现象
天玑 9500 上补帧"流畅但扭曲":运动画面的生成帧是两个位置叠在一起的重影,静止画面完全正常。

### 定位方法(检测程序 0.8 ~ 0.9.5)
1. **真值片段**:240fps 渲染一段平移画面(背景 + 运动色块),每 10 帧取 1 帧作为 24fps 输入,中间帧就是标准答案(`probe` 资源 `gt24.mp4`,电脑上 `bugs/gt/gt240_640x400.gray`)。
2. **多点开关一次跑完**:全屏障、串行提交、线性 AHB、清零后备图像、关闭 LOW 优先级、FP32、不同分辨率 / 光流参数——输出逐像素与对照完全相同,全部排除。
3. **参照 GPU**:同一份代码在电脑模拟器(宿主 Intel Arc,经 gfxstream)上跑。模拟器上 AHB 不能在 GL 与 Vulkan 之间共享,所以加了 framegen 检测接口,输入 / 输出都由 Vulkan 直接上传 / 读回。结果:Intel 上生成帧误差 ≈ 输入采样误差(补帧几乎完美),Mali 上比简单混合还差。
4. **逐级比对中间图像**:mipmaps 阶段 Mali 与 Intel 完全一致;alpha 阶段起严重偏离。mipmaps 着色器不用纹素偏移,alpha 起的着色器每次采样都带 ±1 的 ConstOffset(FP16 / FP32 各 912 处)。
5. **验证修复**:加载着色器时把 `OpImageSampleExplicitLod … ConstOffset` 改写为"坐标 + 偏移 / 图像尺寸"(`android/app/src/main/cpp/lsfg/spvpatch.cpp`,98 个着色器改写后全部通过 spirv-val,C++ 与 Python 实现逐字节一致)。改写后 Mali 与 Intel 的生成帧误差一致(5.78 / 5.78),各阶段中间图像只剩舍入差异;Intel 上改写前后结果不变。

### 同时修正
- 光流参数传反(framegen 要 1 / 比例)。上午"光流精度越低越慢"的测量结论作废。
- 采样器改为 CLAMP_TO_EDGE 在 Mali 上反而更差(仅诊断用,未采用)。

### 排除过的原因(留档)
同步 / 屏障 / 提交顺序、AHB 内存布局(AFBC)、空描述符、队列优先级、FP16 精度、着色器名→资源号映射(52 个名字全部核对)、存储图像格式、子组大小、输入帧提取、GL / CPU / Vulkan 三种读回方式。
