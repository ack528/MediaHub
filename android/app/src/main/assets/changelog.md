# 更新日志

> 每次发布时同步到 GitHub Release 的说明里;手机端「设置 → 关于 → 更新说明」和管理程序「关于 → 更新说明」会显示这里的内容(随程序打包)。
> 版本号分开计:手机端(LocalBrowse)和服务端 / 管理程序(MediaHub)各自一套。

## 手机端 LocalBrowse

### 3.1.0 · 2026-10-17
- **在家自动走内网直连**(设置 → 网络 → 内网直连优先,默认开启):登录后服务器会告诉手机它的所有地址(内网 IPv4 / IPv6、外网穿透地址)。手机和服务器在同一个局域网时,请求自动改走内网地址,不再绕穿透服务器 / 公网;出门或换了网络自动切回外网。「网络」页显示当前线路(内网直连 / 内网穿透 / 公网),可以手动「重新检测线路」。内网直连只用于 HTTPS 服务器,且需要服务端 3.1.0。
- **自动画质**(设置 → 视频播放 → 自动画质,默认开启):播放转码视频时持续估计网速;一旦卡顿(45 秒内停顿 2 次,或一次停顿超过 8 秒)就自动降一档码率,最多降 3 档,降档后 25 秒内不再动;换网络后重新估计。起播时也会按估计的网速直接选合适的码率,不用先卡再降。
- **服务端能看到手机了**:每个请求带上 `LocalBrowse/版本 (Android 系统版本; 机型)` 标识,管理程序的「客户端连接」页面据此显示手机型号和 App 版本。
- 以上需要服务端 3.1.0 才有效(旧服务端保持原来的行为)。

### 3.0.1 · 2026-10-15
- **转码时文件体积显示转码后的预估体积**:视频一旦走服务端转码,播放器顶栏、查看器底部信息条和「信息」面板里的大小都改成「≈预估体积(原 xx)」,按 时长 ×(转码码率 + 约 128 kbps 音频)÷ 8 估算(码率是上限,实际可能更小;不会超过原文件)。切回原画就显示原文件大小。

### 3.0.0 · 2026-10-15
- **转码只提供 6 Mbps 及以下的档位,低码率档位更密**:播放器菜单「画质与解码」里是 原画 / 0.5M / 0.8M / 1M / 1.5M / 2M / 3M / 4M / 5M / 6M;设置里的「转码码率」也改成 自动 / 6 / 5 / 4 / 3 / 2 / 1 Mbps(再高的码率不如直接播原文件)。
- **新增 H.265 转码**:设置 → 视频播放 → 转码编码(自动 / H.264 / H.265)。自动 = 服务端能硬编 H.265(Intel QSV)且手机能硬解就用 H.265:相同码率画质更好,相同画质省 30% ~ 50% 流量。
- **记住播放设置**(设置 → 视频播放,默认开启):在播放器里选过的转码画质 / 编码会记住,切到下一个视频直接用(选了 1.5M 转码,后面的视频默认也是 1.5M);同步到服务器,多台手机共用;服务端还会**提前把相邻两个视频的开头转好**,切换几乎秒开。
- **网络测速**(设置 → 网络测速):服务器延迟(最小 / 平均 / 最大 / 抖动 / 丢包)、下载和上传速度,**每项至少测 15 秒**(可选 15 / 20 / 30 / 60 秒),给出「稳定速度」(去掉前 2 秒慢启动)、全程平均和峰值;可选单连接(接近播放视频)或 4 连接(测最大带宽)。
- **更新下载源与 DNS**(设置 → 关于):显示直连和每个镜像现在的延迟和连通性(绿 / 黄 / 红),可以指定优先使用哪个;内置镜像增加到 8 个;DNS 并发问 6 个 DoH 服务器(哪个先答用哪个),同一个域名有多个 IP 时按 TCP 连接耗时选最快的(参考 Watt Toolkit 的思路),并显示每个 DNS 的延迟。
- **图片加载更快**:网格 / 聊天流里的小图改用服务端生成并缓存好的 WebP 缩略图(几十 KB),不再为了一个小格子下载几 MB 的原图;缩略图失败自动退回原图。登录 / 切换网络后马上预热到服务器的连接。
- 以上需要服务端 3.0.0 才有效(旧服务端保持原来的行为)。

### 2.16.0 · 2026-10-11
- **超分为什么"没效果"——三处修正**:
  - 默认「只对低于此分辨率的视频超分」从 900p 改成 1080p(以前 1080p 视频完全不会超分),并新增 1440p 档位。已经保存过设置的,需要手动改一下。
  - 超分算法从一个重模型(例如 FSRCNNX 中模型)切到别的算法后,之前"跟不上而停用"的状态会清掉重来(以前一旦停用,换成 FSR 也一直是关着的,要退出重进播放)。
  - 说明:着色器自带条件,输出尺寸不到视频的 1.2 倍就不处理——竖屏播放 720p 视频基本触发不了,横屏全屏效果最明显。
- **超分按画面实际清晰度处理**(设置 → 画质增强 → 超分 →「按画面实际清晰度处理」,默认开启)。以前只看标称分辨率,标成 1080p / 4K 但画面其实很糊(低清片源放大来的)的视频,要么因为超过分辨率上限被跳过,要么因为输出不到视频的 1.3 倍被着色器跳过。现在每秒测一次画面清晰度(比较相邻 1 像素和相隔 4 像素的亮度差,边缘被模糊后两者比值会明显下降),判断出画面相当于多大的分辨率,先缩回这个有效分辨率,再交给超分网络放大;「只对低于此分辨率的视频超分」也按有效分辨率判断。播放器统计里会显示「画面偏糊,按 960×600 处理」。真实画面标定与模拟器实测(同一段真人画面造成「标称 1920×1200,实际 1/2、1/3、1/4 清晰度」,和高清原片逐帧对比):实际 1/2 清晰度,FSRCNNX 小模型 PSNR 26.7 → 27.9 dB、锐度 +50%;实际 1/3 清晰度 24.2 → 24.6 dB;实际 1/4 清晰度几乎没有提升(细节在片源里已经不存在了,超分只能补一点边缘,没法凭空还原);本来就清晰的画面不受影响(结果逐位相同)。带明显噪点 / 颗粒的片源会被判成"清晰",不处理,不会误伤。
- **新增超分算法 FSRCNNX(真人 / 影视用,神经网络)**,小、中两档(设置 → 画质增强 → 超分算法,播放器里「真人·小 / 真人·中」)。同一段真人片源,和高清原片逐帧对比:不超分 26.1 dB,FSR 27.2 dB,Anime4K 约 26.2 dB(动画专用,对真人几乎没提升),FSRCNNX 小模型 28.9 dB。中模型很重,多数手机会被自动停用。硬件检测会一并测速并给出推荐。着色器来自 igv/FSRCNN-TensorFlow(LGPL-3.0,作为独立文件放在 assets/shaders/,附 LICENSE-FSRCNNX.txt)。
- **SDR 转 HDR 效果明显增强**:旧曲线只给最亮的一小撮像素加亮、大面积亮区增益压到 0,实际增益约等于 1(例如 600 nit 下,伽马亮度 0.7 的像素只放大 1.06 倍)。新曲线从伽马亮度 0.35 起平滑拉高,到纯白达到设定的峰值,大面积亮区只压低到 40%(同样的像素放大 1.81 倍)。
- **修复:播放中开关「SDR 转 HDR」不生效**。HDR 表面只在画面视图创建时决定,以前如果已经开着补帧 / 超分,再打开 HDR 会一直显示"显示器 / 表面不支持",要退出视频重进才行。现在开关 HDR 会自动重建画面视图。

### 2.13.0 · 2026-10-08

### 2.12.1 · 2026-10-08
- **本地媒体浏览提速**。有的手机上读取本机媒体每次要 10 秒。原来每次进入文件夹列表都强制重新读两遍媒体库,并发的请求还各自排队再读一遍。现在只在媒体库真的变化时才重读(新拍 / 删除会自动感知),图片和视频并行读取,启动时就在后台预读,并发请求共用同一次读取。
- 缩略图限流(同时最多 3 张,避免几千万像素的照片同时解码把 256MB 堆撑满),小尺寸优先用系统缓存的缩略图。
- 日志里新增耗时记录:读取媒体库的图片 / 视频各用了多少毫秒、超过 0.5 秒的接口和超过 0.4 秒的缩略图(含文件大小和尺寸),方便定位哪里慢。

### 2.12.0 · 2026-10-08
- **天玑 / Mali 上补帧不再重影、扭曲**。根因是 Mali 驱动对"带纹素偏移的采样"算错,补帧的光流从第二阶段起全部偏离,运动画面只剩前后帧混合(静止画面正常,所以之前没查出来)。现在加载着色器时把偏移换算进采样坐标绕开,只对 Mali GPU 生效。用有真值的测试片段验证:修复后天玑 9500 的补帧误差和 Intel GPU 一致,约为简单混合的一半。
- 修复光流精度参数传反,光流终于按设置的精度计算。天玑 9500 上一次 ×5 生成从约 36ms 降到约 15ms。
- 补帧不再只限高通处理器,天玑 / Mali 等 Vulkan 设备都可以用。
- 系统短暂把屏幕降到 60Hz 时,补帧会话保留 5 秒以上才释放,不再每次重建(以前每次卡 0.5 ~ 0.7 秒)。
- 补帧倍率按"60Hz 和 120Hz 下都规则"选(24fps 低功耗改为 ×5,原来 ×2 = 48fps 在 60Hz 上每 5 帧停顿一次),上屏节奏更均匀。
- 补帧倍率改用视频声明的帧率决定,4K / 高码率视频解码吃力时不再倍率乱跳、反复重建会话。
- 补帧的输入分辨率上限约 1080p(高帧率视频约 720p),4K 视频在 1080p 级别上生成、上屏时放大,真实帧仍是原分辨率。
- 自动降级的光流精度只在 100% / 75% / 50% 之间调整,再不够就减半生成倍数、降输入分辨率。

### 3.1.0 · 2026-10-17
- **内网穿透**(管理程序 网络 → 内网穿透):服务端托管穿透客户端进程,启动服务时自动拉起、掉线自动重连、健康检查失败自动重启。支持 **frp**(填服务器地址 / 端口 / 令牌 / 协议 tcp·kcp·quic·websocket / 代理类型 / 远程端口 / 连接池 / 心跳 / 连接多路复用 / 带宽限制等,自动生成 frpc 的 TOML 配置,要求 frpc ≥ 0.52)和**自定义命令**(cpolar、natapp、cloudflared 等)。页面显示运行状态、进程信息、链路探测(连接 / 首字节延迟,30 秒一次)、日志(令牌自动隐藏),并按当前配置和探测结果给出提高流畅度的建议(协议改 quic、加大连接池、关掉隧道内加密压缩、http 代理与加密传输冲突等)。**frpc 没有随程序打包**:自己从 frp 的 GitHub 发布页下载,把 frpc.exe 放到 tools\frp\ 下即可。

- **新页面「客户端连接」**:每 2 秒刷新。概况(在线台数、总速度、调度级别和让路统计)、客户端列表(设备名、账号、IP、线路 内网直连 / 内网穿透 / 公网、App 版本和系统、状态 播放中·传输中·浏览中·空闲·离线、正在做什么、当前速度、累计流量、请求数和失败数、首次出现和最近时间)、每台设备的「退出登录」(令牌立即失效)、后台任务状态(压缩已暂停 / 重复检测已降速 / 扫描已降速…)。压缩队列里被暂停的任务会用灰色显示「⏸ 有客户端连接,已暂停」。
